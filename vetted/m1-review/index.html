What Vetted does

Eight steps on every pull request

Open a step to see why it exists and where its evidence is.

01Gate the runShadow mode reviews everything but only writes an audit record; opt-in reviews labelled pull requests and comments; forks get the free mock›

Why it matters: a team can watch what the AI would say before letting it say anything. That's the gradual rollout IMDA's frameworks describe. Only pull_request events are accepted: pull_request_target would hand secrets to fork code.

Evidence: #15, a 9-row test table of mode × label × fork × key. Config is read from the base commit, so a pull request can't weaken its own review (ADR 0007).

02Keep sensitive files out.env files, keys, credential files, lockfiles, generated code and binaries are never sent; oversized files are skipped whole and listed›

Why it matters: the cheapest leak to prevent is a file that never leaves. The deny list is a floor: a team's config can add to it but can never re-allow a .env. Files are never cut in half, because a truncated file would be reviewed as if it were complete.

Evidence: #16. A canary that only the deny list can stop leaks when the deny list is removed.

03Scrub secretsgitleaks' 221 rules run with a linear-time regex engine, plus an entropy check for secrets no rule names›

Why it matters: using the industry's standard rule set is easy to defend, and proving the port faithful is what makes it credible: 0 misses against the real gitleaks binary. Where gitleaks would let a secret through (for example by honouring an "allow" comment written by the same person whose secret it is), Vetted is deliberately stricter.

Evidence: #17, ADR 0010, the parity table and the entropy calibration.

04Scrub Singapore personal dataNRIC/FIN (including mistyped ones), phone numbers and emails become <NRIC>, <PHONE>, <EMAIL>›

Why it matters: PDPC's guidance treats NRIC numbers as especially sensitive, and sending them to an overseas AI provider is a transfer out of Singapore. The rules live in their own repository with checksummed releases, and Vetted's implementation passes 184 / 184 shared test cases, the same ones Discreet's Go version will have to pass.

Evidence: #18, sg-pii-rules v0.1.0-rc.1. VALIDATORS.md says plainly that the NRIC checksum was never officially published.

05Check the budgetEach review has a hard worst-case cost; today's worst case must fit the daily budget, or the free mock is used›

Why it matters: the brief caps spend. Measuring spend after the fact can't stop a runaway, but a bound computed from hard caps can. Diff size is capped in bytes, and a token is never smaller than a byte, so the input cost has a true ceiling. Anything uncertain, such as an unknown model price, falls back to the mock.

Evidence: #19, ADR 0004, ADR 0011, and the cost bound below.

06Ask the model, safelyThe diff is wrapped in markers with a random nonce and labelled untrusted; no tools; strict JSON schema; store: false›

Why it matters: prompt injection is OWASP's number one LLM risk. The model is told the diff is data, not instructions, and an attacker can't fake the end of the data block without guessing 64 random bits. The client refuses to exist inside the test suite with real network access, so tests can never spend money.

Evidence: #19, src/model/prompt.ts, src/model/openai.ts.

07Validate, detect, and commentInvalid output is discarded; injection attempts are reported by rules; comments are tagged [AI], always posted as COMMENT›

Why it matters: the model's output is untrusted too. Links and images are removed before posting, because a rendered image URL is a known way to leak data out of an AI system. Injection findings are posted even when the model's output is unusable, so breaking the model can't also hide the attack. There's no code path that approves or requests changes, and a test checks for it.

Evidence: #20, ADR 0012. CodeQL caught my first HTML sanitiser, which could be bypassed; it's fixed and has a test.

08Leave an audit recordEvery run, including skipped and failed ones: prompt hash, model, tokens, cost, budget, scrub counts; never code›

Why it matters: governance needs evidence of what happened, and the evidence mustn't become a leak itself. The record has hashes and counts only, is checked against a schema, and is uploaded as a workflow artifact kept for 30 days. It's the data Milestone 3's dashboard will be built on.

Evidence: #21. Real records: Vetted reviewing its own #21 and Discreet's first pull request.

Known gaps, stated in the docs

  • Base64-encoded secrets aren't decoded (gitleaks does this); the entropy check covers long ones.
  • Names and addresses aren't detected; that needs NER, planned for Discreet.
  • A pull request can edit its own workflow file. Vetted is advisory, so it's deliberately not a required check; the batch review is the backstop.

Small calls I made on my own

  • Closed four major-version Dependabot upgrades: TypeScript 7 breaks the build, and Node 26 types don't match the runtime.
  • Made CodeQL and the canary suite required checks, after CodeQL caught two real issues.
  • Size cap in bytes, not characters, so the cost bound is real. Entropy threshold 4.3. Look-alike NRICs scrubbed too.
  • Vetted reviews its own pull requests from a pinned, merged version, never the code under review.

Interview crib

If you're asked about Milestone 1

  1. "What is it?" A GitHub Action that lets a team use AI for code review without sending secrets or Singapore personal data to the provider, without letting text in the code steer the AI, and without the AI ever approving anything.
  2. "How do you know it doesn't leak?" A canary suite pushes pull requests full of fake passwords and identity numbers through the real code, even against a model that repeats everything back, and searches every output for them. Zero leaks. I also proved it fails when I remove a protection.
  3. "Did you write this yourself?" Claude Code drafted it under a written brief. Every change went through a pull request with CI. I merged the early ones myself, then chose an integration branch so the AI could merge into staging while I review the batch before main. Every AI mistake is logged with how it was caught.
  4. "What would you do differently?" I'd set the API key on day one: the biggest gap in the evidence is that no real model has been measured yet.
  5. "Why Singapore-specific?" The NRIC is treated as especially sensitive by PDPC, the checksum was never officially published, and sending personal data to an overseas AI provider is a transfer out of Singapore. The controls matrix maps each feature to the specific clause.
